### Why these two ratios?

| Rank | Ratio (feature)                               | Why it matters (financial‑ratio theory) |
|------|----------------------------------------------|------------------------------------------|
| 1️⃣   | **Working Capital / Total Assets** (WC/TA)   | Measures short‑term liquidity relative to the firm’s asset base. Very low values often precede cash‑flow crises. |
| 2️⃣   | **Retained Earnings / Total Assets** (RE/TA) | Captures the cumulative profitability retained in the business. Negative or near‑zero values signal that earnings have been insufficient to build a cushion. |
| (Other ratios – e.g., EBIT/TA, Sales/TA, Book‑Equity/Book‑Liabilities – are also useful, but they are not needed to keep the tree at depth 2.) |

**Python implementation of the depth‑2 decision tree**

```python
def predict(X: dict):
    """
    Predict whether a company went bankrupt (target = 1) or not (target = 0)
    using the two most‑informative financial ratios.

    Expected keys in the input dictionary *X* (exact spelling, case‑sensitive):
        - 'WC/TA'   : Working Capital / Total Assets
        - 'RE/TA'   : Retained Earnings / Total Assets
        - 'EBIT/TA' : Earnings Before Interest and Tax / Total Assets   (unused)
        - 'S/TA'    : Sales / Total Assets                               (unused)
        - 'BVE/BVL' : Book Value of Equity / Book Value of Liabilities   (unused)

    Returns
    -------
    prediction : int
        0 → company did **not** go bankrupt  
        1 → company **did** go bankrupt
    nodes : list[int]
        Truth values of the inner nodes (1 = condition satisfied, 0 = not satisfied)
        * nodes[0] – result of the root split  (WC/TA ≤ 0.12)
        * nodes[1] – result of the right‑child split (RE/TA ≤ 0.03)

    Note
    ----
    The thresholds 0.12 and 0.03 are typical cut‑offs that emerge from
    empirical Z‑score studies.  In a real‑world setting you would let a CART
    algorithm learn the exact numbers from your training data.
    """
    # ------------------------------------------------------------------
    # 1️⃣  Evaluate the two inner‑node conditions (store as 1/0)
    # ------------------------------------------------------------------
    nodes = [0, 0]                     # initialise list of length 2
    nodes[0] = int(X['WC/TA'] <= 0.12)   # root node
    nodes[1] = int(X['RE/TA'] <= 0.03)   # right‑child node (evaluated always)

    # ------------------------------------------------------------------
    # 2️⃣  Follow the tree logic
    # ------------------------------------------------------------------
    if nodes[0] == 1:                     # WC/TA ≤ 0.12  → leaf “Not bankrupt”
        prediction = 0
    else:                                 # WC/TA  > 0.12 → go to right child
        if nodes[1] == 1:                 # RE/TA ≤ 0.03 → leaf “Bankrupt”
            prediction = 1
        else:                             # RE/TA  > 0.03 → leaf “Not bankrupt”
            prediction = 0

    return prediction, nodes
```

### How the function works

| Step | Condition evaluated | Stored in `nodes[i]` (1 = True, 0 = False) | Decision taken |
|------|----------------------|-------------------------------------------|----------------|
| **Root** | `X['WC/TA'] <= 0.12` | `nodes[0]` | If **True** → prediction = 0 (safe) |
| **Right‑child** (only reached when `nodes[0]==0`) | `X['RE/TA'] <= 0.03` | `nodes[1]` | If **True** → prediction = 1 (bankrupt) otherwise → prediction = 0 |

The returned `nodes` list gives a full, binary trace of the path the sample followed through the inner nodes, which is exactly what you asked for. Feel free to plug the function into your code base and pass a dictionary that contains the required keys.
